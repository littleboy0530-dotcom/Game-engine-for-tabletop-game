# 보드게임 프로토타이핑 엔진 설계

## 목표

아이디어만 있으면 누구나 보드게임 MVP를 돈 들이지 않고 빠르게 만들고 재미를 검증할 수 있는 도구.

### 원칙 (판단이 갈리면 위에서부터 우선)
1. **초보자가 다룰 수 있어야 함**: 프로그래밍 초보도 룰북을 옮기듯 작성할 수 있어야 한다.
2. **빨리 만들 수 있어야 함**: 엔진도, 엔진으로 만드는 게임도.
3. **상태를 바꾸는 곳은 rule 하나뿐**.
4. **실물 구현은 신경 쓰지 않음**: 점수나 돈은 그냥 숫자다. 실물화는 제작자가 정한다.

### 범위
덱스터리티(물리엔진이 필요한 장르)를 제외한 대부분의 보드게임.
자동 대전은 구조상 가능하게만 열어 둔다 (솔로 모드용 스크립트 플레이어는 지원).

### 검증 대상 게임
| 장르 | 게임 |
|---|---|
| 추상전략 | 체스, 장기 |
| 덱빌딩 | 도미니언, 어센션 |
| 복합 | 반지의 제왕: 가운데땅의 결투, The Old King's Crown |
| 타일 놓기 | 카르카손 |
| 주사위 | 모노폴리, 매지컬 애슬릿 (야단법석 달리기) |
| 셋 콜렉션 | 마작, 포커 |
| TCG | 매직 더 개더링 (카드 효과 스크립팅) |

전통 게임(체스, 장기, 마작, 포커)은 그대로 구현해 검증한다.
상용 게임은 그대로 재현하지 않고, **같은 메커니즘을 쓰는 오리지널 테스트 게임**으로 엔진 기능을 검증한다.

---

## 핵심 아이디어: 게임 = 두 개의 그래프

| 그래프 | 표현하는 것 | 노드 | 연결 |
|---|---|---|---|
| **보드 그래프** | 공간: 무엇이 어디에 있고 어디로 갈 수 있는가 | 존 | 간선 |
| **루프 그래프** | 흐름: 어떤 순서로 진행되고 무엇을 할 수 있는가 | 페이즈, Action, 하위 루프 | 전환 |

두 그래프의 공통 규칙
- 연결(간선, 전환)은 **스크립트 없는 데이터**다.
- 스크립트는 **노드에만** 붙는다.
- **그림이 거짓말하지 않는다**: 그래프에 없는 연결은 실제로도 일어나지 않는다.

그래서 **그래프 에디터 하나로 보드와 룰을 모두 만든다.** 룰북의 "턴 진행 순서" 그림을 그리면 게임이 돌아가는 것이 이 엔진의 킬러 기능이다.

## 1. 계층 구조

```
ui        자동 생성. rule을 통해서만 동작
  ▲ 현재 노드, 선택지        │ 플레이어의 선택
  │                          ▼
rule      루프 그래프 + 이벤트 시스템 + 플레이어 정보 + 공용 정보
  │ 메서드 호출 (판정 / 효과)
  ▼
component 주사위, 말, 타일, 카드, 보드 그래프
```

- 게임 상태 = component 배치 + rule 데이터 + 루프의 현재 위치
- component의 메서드는 스스로 실행되지 않고 rule이 호출할 때만 동작한다 (rule = 진입점, 나머지 = 클래스).

## 2. component 계층

### 공통 속성
| 속성 | 설명 | 예 |
|---|---|---|
| `tags` | enum 태그 | 종류 구분, 판정 조건 |
| `owner` / `controller` | 소유자 / 조종자 | MTG 조종권 변경 |
| `face` | 앞면 / 뒷면 | 카드, 마작 패 |
| `rotation` | 회전 단계 | MTG 탭, 타일 방향 |
| `counters` | 이름 붙은 숫자 | +1/+1 카운터 |
| `attached` | 다른 컴포넌트에 부착 | 장비, 오라 |
| `props` | 제작자 정의 데이터 | 가격, 공격력 |

### 종류
| 종류 | 특징 |
|---|---|
| 주사위 | 면을 자유롭게 정의 (숫자, 기호, 복수 값) |
| 말 | 이동 판정 `moveCandidates()` |
| 타일 | 두께가 있어 쌓을 수 있음. 변 레이블, 하위 존 |
| 카드 | 두께 없음. 앞/뒷면, 회전, 효과 메서드 |
| 보드 | 존과 간선의 그래프 |

### 보드 그래프
- 좌표계: `square`, `hex`, `track`, `none`
- 게임 중 존 추가/삭제 가능
- 조회: `zoneAt(index)`, `neighbors(zone)`, `zonesWithTag(tag)`

**존**: 공간을 차지하는 컨테이너
| 속성 | 설명 |
|---|---|
| `index` | 좌표 (좌표계가 없으면 이름) |
| `tags` | enum 태그 (`궁성`, `숲`, `물`) |
| `accepts` | 받을 수 있는 컴포넌트 종류 (선언) |
| `layout` | `free` / `pile` / `row` |
| `visibility` | `public` / `owner` / `hidden` / `topOnly` |
| `canAccept()` | 판정 스크립트 |

**간선**: 스크립트 없는 연결. 기본 양방향, 단방향 가능.

**이동 판정**: 최종 이동 가능 = 말의 후보 ∩ 존이 받아주는 곳

## 3. rule 계층: 루프 그래프

### 3.1 노드
| 노드 | 진행 | 스크립트 |
|---|---|---|
| 시작 / 끝 | 루프의 입구와 출구 | 없음 |
| 페이즈 | 엔진이 자동 진행 | `onEnter`(실행), `next`(판정) |
| Action | 플레이어가 선택해서 들어감 | `options`(판정), `execute`(실행), `limit`(선언) |
| 하위 루프 | 안에 루프 그래프를 가짐 | 공통 Action 보유 가능 |

페이즈와 하위 루프에는 행동하는 플레이어를 선언한다.
- `current`: 현재 플레이어
- `all`: 모두 동시에. **모든 선택을 모은 뒤 한꺼번에 반영**하며, 제출된 컴포넌트는 페이즈가 끝날 때 동시에 공개된다 (`revealed` 이벤트).
- `each`: 턴 순서대로 한 명씩

### 3.2 진행 규칙
1. 페이즈에 들어가면 `onEnter`를 실행한다.
2. 나가는 화살표가 Action 노드로 향하면 멈추고 플레이어의 선택을 기다린다.
3. 나가는 화살표가 페이즈나 하위 루프로만 향하면 `next`가 그중 하나를 고른다. 연결되지 않은 노드를 반환하면 오류. 화살표가 하나면 `next` 생략 가능.
4. Action을 선택하면 `execute`를 실행하고 그 노드의 나가는 화살표를 따라간다.
5. 하위 루프는 안쪽 시작 노드부터 진행하고, 끝 노드에 닿으면 상위 루프의 다음 화살표로 간다.
6. **입력 없이 전환이 32번 이어지면 멈추고** 돌던 경로를 에디터에 표시한다.

### 3.3 Action 노드
```lua
return {
  limit = { count = 1, per = "turn" },        -- turn / phase / round

  options = function(game, player)            -- 판정: 구체적인 선택지
    return player.hand:cardsWithTag("액션")
  end,

  execute = function(game, player, card)      -- 실행
    player.vars.actions = player.vars.actions - 1
    game:play(card)
  end,
}
```
- 액션 종류(노드)와 선택지(`options`)를 나눈다. 선택지가 없으면 비활성.
- ui는 선택지를 대상 컴포넌트에 붙여 보여준다. 대상 없는 액션만 버튼.
- 세부 선택은 `execute` 안에서 `choose`로 받는다.
- 여러 단계의 복잡한 액션은 Action 다음에 하위 루프를 연결한다.
- 한 페이즈에 연결된 Action들은 순서 없이 섞어 쓸 수 있다. 순서가 필요하면 페이즈를 나눈다.

### 3.4 공통 Action
하위 루프에 선언하면 그 안의 모든 페이즈에서 사용 가능. 실행 후 원래 노드로 돌아간다. 특정 페이즈에서 제외 선언 가능. 에디터에서는 하위 루프 테두리에 붙여 표시한다.

### 3.5 `choose`의 동작 (기술 검증 결과 반영)
- 입력이 필요하면 엔진은 **현재 액션의 상태 변경을 되돌리고, 플레이어에게 묻고, 지금까지의 답을 가지고 액션을 처음부터 다시 실행**한다.
- 코루틴으로 멈추는 방식은 JS 엔진 함수를 거치면 동작하지 않아 채택하지 않았다 (`spike/spike1.mjs`).
- 그 결과 **모든 상태는 `game` 안에만 둔다.** Lua 전역 변수에 쓰기는 엔진이 막는다.

### 3.6 상태
- 공용 정보: `game.vars`
- 플레이어 정보: `player.vars`, 턴 순서
- 현재 플레이어 변경(마작의 퐁 등)은 `execute`에서 지정. 노드 전환과 별개.

### 3.7 플레이어 종류
- `human`: 사람이 ui로 선택
- `script`: `choose`가 오면 제작자가 쓴 Lua 함수가 선택. 솔로 모드의 오토마 규칙을 옮기는 용도.

### 3.8 이벤트 시스템
- 상태가 바뀔 때 이벤트 발생 (`moved`, `passed`, `drawn`, `rolled`, `revealed`, `phaseEnter`). 사용자 정의 이벤트 가능.
- 컴포넌트가 `on(이벤트, 함수)`로 리스너 등록. 실행은 rule이 한다.
- 처리 방식: 기본 **큐(FIFO)**, `game:chain(...)`으로 구간 단위 **체인(LIFO)** 전환.
- 동시 발동 순서: 기본은 현재 플레이어부터 턴 순서. rule에서 변경 가능.
- **연쇄 한도**: 처음 이벤트 하나에서 이어진 효과 총 32회.
- **사전 이벤트**: `beforeRoll`, `beforeMove` 등에서 값 변경/취소 (다시 굴리기, 대체 효과).
- **우선순위 반응 창구**: 여러 플레이어가 동시에 비공개로 반응을 고르고 우선순위가 높은 것만 실행. 받아들일 개수 지정 가능.

### 3.9 수정값, 기록, 가상 실행
- 수정값: 지속 효과는 수정값으로 등록하고 `game:value(c, "power")`로 계산된 값을 얻는다.
- 기록: `game.history`
- 가상 실행: `game:simulate(fn)`은 복사본에서 실행하고 결과만 반환.

### 3.10 무작위와 재현
- 무작위는 `game:roll()`, `game:shuffle()`로만. 난수 상태는 게임 상태 안에 있다.
- **저장 = 시드 + 입력 기록.** 불러오기, 되돌리기, 리플레이, 핫 리로드 모두 기록 재생으로 처리 (`spike/spike2.mjs`에서 결정성 확인).

### 3.11 표준 라이브러리
패턴(족보, 역), 영역(연결, 닫힘), 경로(이동 비용), 방향(막힐 때까지 읽기).

## 4. ui 계층
MVP에서는 자동 생성한다.
- 2D 탑뷰 렌더링. 두께는 쌓인 높이와 그림자로 표현. 이미지 없으면 이름/색/숫자로 표시.
- 선택지를 대상 컴포넌트에 붙여 표시.
- 핫시트: 차례가 바뀌면 화면을 가려 비공개 정보를 숨김. `all` 페이즈에서도 앞사람 선택을 숨김.
- 정보 패널: 플레이어/공용 정보, 이벤트 로그, 현재 루프 위치.

### 테스트 도구
루프 실시간 하이라이트, 노드 중단점, 되돌리기, 저장/불러오기, 시드 고정, 수동 수정 모드, 핫 리로드, 오류 위치 표시.

## 5. 스크립팅
**언어: Lua** (wasmoon, Lua 5.4 WASM).

| 종류 | 위치 | 권한 |
|---|---|---|
| 판정 | 페이즈 `next`, Action `options`, 말 `moveCandidates`, 존 `canAccept`, 수정값 | 읽기 전용 (엔진이 강제) |
| 실행 | 페이즈 `onEnter`, Action `execute`, 카드 효과, 리스너 | 상태 변경 가능 |

개발자는 메인 함수나 `while` 루프를 직접 쓰지 않는다. 블록 코딩은 MVP 이후.

| 매지컬 애슬릿 | track | 경주 루프 > 턴 루프 | `passed` 리스너, 사전 이벤트 |

## 8. 기술 스택과 개발 순서
- 웹 앱: TypeScript 엔진 코어, wasmoon(Lua), React + React Flow(그래프 에디터)
- 렌더링: 1단계는 SVG로 그린다. 구현이 빠르고 테스트하기 쉬워서다. 컴포넌트 수가 많아져 느려지면 PixiJS로 바꾼다.

1. 코어 + 그래프 에디터 → 체스, 장기
2. 카드와 비공개 정보, 하위 루프, 공통 Action → 도미니언형, 포커, 모노폴리형
3. 이벤트, 사전 이벤트, 반응 창구, `all` 동시 제출, 스크립트 플레이어 → 매지컬 애슬릿형, 마작, 어센션형, Old King's Crown형
4. 동적 보드, 타일 하위 존 → 카르카손형, 가운데땅의 결투형
5. 체인, 수정값 → MTG형

## 1단계 구현 현황

완료: 엔진 코어, 루프 그래프 실행기, Lua 연동, 자동 생성 ui, 루프 그래프 보기, 체스, 장기, GitHub Pages 배포.
그래프 **편집** 기능은 아직 없다. 지금은 yaml 파일로 그래프를 쓰고, 화면에서는 보기와 현재 위치 표시만 된다.

### 구현하면서 정한 것
- **스크립트 함수 모양**: 노드 스크립트는 `(game, player, option)`, 컴포넌트 스크립트는 자기 자신이 먼저 온다: `moveCandidates(piece, game)`, `canAccept(zone, piece, game)`.
- **존 판정 스크립트**는 존 태그 이름으로 찾는다. `components/zones.lua`의 `["물"] = { canAccept = ... }`는 `물` 태그가 붙은 모든 존에 적용된다.
- **Action 노드에 `options`가 없으면** 선택지 하나짜리 버튼이 된다 (예: 기권).
- **게임 종료**: `game:win`은 결과만 기록한다. 루프가 `end` 노드에 닿거나, 결과가 있는 상태에서 Action 입력을 기다리게 되면 게임이 끝난다.
- **공용 함수**는 `use("lib/x.lua")`로 불러온다. 모듈은 샌드박스에서 실행되며, 불러온 뒤에는 전역 변수 쓰기와 모듈 테이블 수정이 막힌다. `math.random`도 막혀 있다.
- **되돌리기**는 입력마다 상태 사본을 저장해서 처리한다. 저장/불러오기와 핫 리로드는 같은 입력 기록을 재생하는 방식으로 붙일 예정이다.
- **보드 좌표**: `(0, 0)`이 왼쪽 아래, 첫 번째 플레이어가 아래쪽.
- **장기 규칙 범위**: 빅장과 한수쉼은 아직 없다. 둘 수 있는 수가 없으면 무승부로 처리한다.
- **체스 규칙 범위**: 3회 동형 반복과 기물 부족 무승부는 아직 없다.

### 성능 (Node, 1수당)
- 체스: 약 60ms (합법 수 계산 포함)
- 장기: 약 90ms
- 판정 스크립트에서 상대의 모든 수를 만들어 보는 대신, 왕 위치에서 거꾸로 공격을 찾는 방식으로 장기를 약 5배 빠르게 했다 (1수당 약 440ms → 90ms). 게임 제작자에게도 같은 방식을 권한다.

## 2단계 구현 현황

완료: 카드, 주사위, 비공개 정보, 셔플, 트랙 보드, 하위 루프 화면 표시, 공통 Action, Action 횟수 제한.
검증 게임: 포커(텍사스 홀덤), 작은 영지(도미니언형 오리지널 덱빌딩), 한 바퀴 부동산(모노폴리형 오리지널 주사위 게임).

### 구현하면서 정한 것
- **컴포넌트 종류**: 말, 카드, 주사위를 같은 컴포넌트로 다루고 `kind`로 구분한다. 타일(두께, 쌓기)은 4단계(카르카손형)에서 넣는다.
- **카드 정의**: `game.yaml`의 `cardTypes`나 CSV(`cards:`). CSV의 알려진 열 외에는 모두 `props`가 되고, `props`는 종류별 기본값이다. 컴포넌트에서 값을 바꾸면 그 컴포넌트에만 저장된다.
- **플레이어별 존**: `perPlayer: true`로 선언하면 `hand@a`처럼 플레이어마다 만들어진다. 스크립트에서는 `player:zone("hand")`.
- **가시성**은 존 단위로 정한다: `public`, `owner`, `hidden`, `topOnly`. 컴포넌트가 뒷면(`face: down`)이면 존과 상관없이 아무도 못 본다. 규칙 스크립트는 심판이라 항상 모든 것을 본다.
- **핫시트 가림막**: `owner` 존이 있는 게임은 입력할 사람이 바뀔 때마다 화면을 가리고 "○○에게 넘겨주세요"를 띄운다.
- **공통 Action**: 연결을 그리지 않는 Action 노드다(`common: true`). 그 노드가 속한 루프와 그 안쪽 하위 루프 어디서든, 플레이어가 기다리는 곳이면 쓸 수 있고, 실행 후 원래 노드로 돌아온다. 공통 Action에 연결을 그리면 오류다. 특정 노드에서 빼려면 그 노드에 `exclude`를 적는다.
- **Action 횟수 제한**: `limit: { count, per: 노드 }`. `per` 노드에 들어갈 때마다 횟수가 초기화된다. "턴마다 1번"은 턴 루프 노드를 `per`로 적으면 된다. 엔진에 "턴"이라는 개념을 따로 두지 않고 그래프의 노드로 표현한다.
- **choose를 기다리는 동안의 화면**: 스크립트는 입력을 받으면 처음부터 다시 실행되므로 기다리는 동안 실제 상태는 스크립트 실행 전이다. 그러면 약탈자 카드처럼 효과가 반쯤 진행된 상태를 화면에서 볼 수 없어서, 엔진이 진행 중인 상태를 따로 보관해 화면(`engine.view`)에 보여준다. 규칙과 기록 재생은 영향을 받지 않는다.
- **루프 그래프 화면**은 지금 위치가 있는 가장 안쪽 하위 루프를 보여주고, 위쪽 경로로 다른 단계로 이동할 수 있다. 지금 고를 수 있는 Action만 강조하고, 연결은 되어 있지만 지금 고를 수 없는 Action은 흐리게 보여준다.
- **트랙 보드**: `coords: track`. 칸이 순서대로 이어지고 기본은 고리 모양이다. 화면에서는 사각형 둘레에 그린다.
- **패턴 판정 라이브러리**: 포커 족보는 아직 게임 쪽 `lib/poker.lua`에 있다. 마작(3단계)을 만들 때 공통 부분을 엔진 표준 라이브러리로 옮긴다.

### 아직 없는 것
- `all` / `each` 행동 플레이어(동시 제출)와 이벤트 시스템은 3단계.
- 포커: 블라인드 인상, 딜러 버튼의 데드 버튼 규칙은 없다.
- 작은 영지: 반응 카드(공격 막기)는 이벤트 시스템이 생기는 3단계에서 추가한다.
- 한 바퀴 부동산: 플레이어 간 거래, 집 짓기, 감옥은 없다.

## 부록: 기술 검증 (`spike/`)
| 검증 | 결과 |
|---|---|
| Lua 코루틴으로 `choose`에서 멈추기 | Lua만 거치면 성공, JS 엔진 함수를 거치면 `attempt to yield across a C-call boundary`로 실패 |
| 상태 되돌림 + 다시 실행 방식 | Lua → JS → Lua 경로에서도 성공 |
| 시드 + 입력 기록 재생 결정성 | 동일 상태 재현 성공, 다른 시드는 다른 결과 |

wasmoon 1.16 주의점
- JS 예외 객체는 Lua를 거치면 문자열로 바뀐다. 입력 대기는 엔진 플래그로 판별한다.
- JS 함수가 Lua에 `null`을 반환하면 런타임 오류가 난다. 엔진 API 반환값을 정리해서 넘긴다.
